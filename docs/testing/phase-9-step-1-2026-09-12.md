# Phase 9, step 1 — Security review and dependency remediation

**Date:** 2026-09-12. **Status:** step 1 complete and locally verified on the Windows workstation of the [build-and-verify run](build-verify-2026-09-09.md), on top of commit `bb43a46` (Phase 9 plan). Step 2 is next. Every number below was produced in this run.

## Delivered behaviour

- **Security headers and a nonce-based CSP** (`lib/security/headers.ts`, `middleware.ts`, `next.config.ts`): every response carries `X-Content-Type-Options: nosniff`, `Referrer-Policy: strict-origin-when-cross-origin`, `X-Frame-Options: DENY`, a `Permissions-Policy` (camera, microphone and geolocation off; payment for the store, Stripe and PayPal) and `X-DNS-Prefetch-Control`. Every page response carries a Content-Security-Policy with a per-request nonce and `'strict-dynamic'` (Next.js nonces its own scripts from the policy it receives in the request headers; the consent-defaults snippet reads the nonce from `x-nonce`; JSON-LD data blocks are never executed and carry none), `frame-ancestors 'none'`, `object-src 'none'`, `base-uri 'self'`, `form-action 'self'`, the Stripe, PayPal, Google Tag Manager and Turnstile hosts for frames and connections, and `report-uri /api/csp-report`. The policy ships **report-only** (`CSP_ENFORCE=false`, the launch default); the new sink `POST /api/csp-report` logs one compact line per report (both wire formats), never echoes or stores the body and is rate-limited per client.
- **Backlog B14 — login without JavaScript:** `LoginForm` hands the Server Action to the form directly; every outcome is a redirect and the page renders the error from its search params. The pending state uses `useFormStatus`; Turnstile still needs a script to mint its token (inherent to the challenge; the test harness token is a hidden field).
- **Middleware gate:** anonymous requests to `/admin…` and `/racun…` are turned away by the middleware itself, before any page guard runs: a 307 to `/prijava` with a relative `Location` and a relative `callbackUrl` (`/prijava?callbackUrl=%2Fadmin`), which Next.js derives from the request's own origin so it is right behind any reverse proxy. The page guards keep re-checking the session (finding F6, F7).
- **Backlog B15 — maintenance password hashing:** the `maintenance` Setting stores a bcrypt hash (`passwordHash`), never the password; the settings form takes a *new* password (blank keeps the stored hash) and shows whether one is set; enabling the lock without any hash is refused; the unlock action compares with bcrypt, caps the input and bounds guesses per client (10 per 10 min); the middleware keeps reading only `enabled`. The seed and the e2e helper store a hash; a legacy plain-text row can no longer unlock anything.
- **Login attempt limits:** the password step is bounded per address (10 per 15 min) and per client (200 per 15 min) before the Turnstile check and the hash compare; an exceeded address gets the `rate_limited` outcome and its own message on `/prijava`. The TOTP step keeps its Phase 7 limit.
- **Coupon-link probing:** `/koda/{CODE}` answers 429 with `Retry-After` after 30 lookups per client in ten minutes.
- **Input boundaries closed:** the back-in-stock action validates the product slug and caps the challenge token; the newsletter action caps the token; the invoice route validates the order number param; the maintenance unlock validates its input.
- **Cookies:** `nasmeh_consent` is now `httpOnly` (no script reads it; the provider receives the parsed choice from the server).
- **Log hygiene:** seven `console.error` sites that dumped whole error objects (which can carry the submitted address inside a Prisma error) log the error name only; the Auth.js logger names the cause instead of dumping it.
- **Docker:** the three build stages pin `node:20-alpine` by digest and the runner installs the exact Prisma CLI version of the lockfile.
- **`.env.example`** documents `CSP_ENFORCE`.

## Findings fixed during the step

| # | Finding | Resolution |
|---|---|---|
| F1 | Under the report-only policy the first sweep logged `script-src` violations for `eval` on the checkout, the account pages and every admin form: Zod 4 compiles object parsers with `new Function` in the browser | `instrumentation-client.ts` sets `z.config({ jitless: true })` before any client code runs (the server keeps the JIT); the sweep and the admin pass log no violation afterwards |
| F2 | The invoice route's new order-number bound (40 characters) refused the account spec's 42-character fixture numbers, so two regression tests got 404 | Both PDF routes bound the number at 64 characters — production numbers are 13 characters; the bound exists to cap the input, not to shape it |
| F3 | Giving the JSON-LD blocks a nonce changed their markup, which the SSR specs parse with an exact tag; data blocks are never executed, so the policy does not apply to them | `JsonLd` renders the bare tag again and the hardening spec asserts the nonce on the consent snippet only |
| F4 | `npm update` and `nodemailer@10` each split `@auth/core` into two copies (Auth.js beta pins its core and declares nodemailer as a peer in an older range), breaking the adapter types | Both reverted; the advisories are dispositioned in the table above and the constraint is recorded for the post-launch upgrade window |
| F5 | The first version of the login-limit browser test outran the server: after the first redirect the page already sat on `/prijava?error=credentials`, so later waits returned at once and attempts overlapped | The test starts every attempt from a fresh `/prijava` navigation |
| F6 | Passing a custom handler to the Auth.js middleware (needed to forward the nonce request header) made Auth.js ignore the boolean of `callbacks.authorized`: anonymous `/admin` and `/racun` requests were no longer redirected by the middleware, only by the page guards (every test still passed; the container smoke showed a redirect without the callback parameter) | The handler applies the same `authorized` callback itself and redirects to `/prijava?callbackUrl=…`; the hardening spec and the smoke now assert the middleware-level redirect on `/admin`, `/admin/narocila` and `/racun` |
| F7 | The report sink recorded real `connect-src` reports beside the spec's synthetic ones: an RSC prefetch of a guarded page (the account link on a product page, a sidebar link a manager may not open) followed the middleware's sign-in redirect to `http://localhost:4317/…` while the browser sat on `127.0.0.1:4317` — cross-origin, so `'self'` refused it and the router fell back to a full navigation. Root cause in Next.js, not in the redirect target: its `NextURL` class normalizes any loopback IP to `localhost` (in the middleware's `request.nextUrl` and again in every redirect `Location`), while the router relativizes a middleware `Location` only when its origin matches the literal bind address (`initURL`); bound to 127.0.0.1 the two never agree, so every middleware redirect left the harness server absolute on `localhost`. Building the `Location` from the forwarded host did not help either — the same normalization rewrote it. Production binds `0.0.0.0` and was never affected | The middleware issues the canonical redirect on the request's own origin (`request.nextUrl.clone()`), which Next.js turns into a relative `Location` before it leaves the server, with a relative callback path (`/prijava?callbackUrl=%2Fadmin`, the RSC cache-buster stripped) — right behind any reverse proxy without trusting a header. The Playwright server binds through `localhost` resolved IPv4-first (`HOSTNAME=localhost`, `NODE_OPTIONS=--dns-result-order=ipv4first` in `playwright.config.ts`), so it still listens on 127.0.0.1 where the tests connect while Next's own origin matches its normalized form. The hardening spec asserts the relative `Location` on the three gated paths and the sweep hovers the account link on a product page so the prefetch-then-redirect path runs |

## Deviations from the step 1 design

1. **CSP stays report-only** at the end of the step: every local run (the full suite, the storefront sweep with a checkout, the admin pass) is clean, but the payment SDKs (Stripe.js, the PayPal SDK) and the live Turnstile widget never loaded here because the harness has no keys. Enforcement is therefore folded into gate **G1**: run the sandbox acceptance with `CSP_ENFORCE=true`, watch the `[csp]` lines, add any host the SDKs need to `buildCsp`, then keep enforcement on for launch. Until then the header is Report-Only and the sink logs whatever real browsers report.
2. **Dependencies are accepted, not upgraded** — see the disposition table; the plan foresaw bumps "within their major where a patched release exists", and no such release exists for the flagged packages.
3. **Turnstile and JavaScript:** the login form posts natively, but a real Turnstile site key still needs a script to mint the token; the no-JavaScript path is complete for the form, the action and the error display.

## Operations notes

- `CSP_ENFORCE=true` switches the same policy to enforcement without a rebuild; watch `[csp]` lines in the server log (the report sink) for a few days of real traffic before flipping it, and after adding any third-party script.
- The maintenance password is set on the marketing settings screen; the stored value is a hash, so a forgotten password is replaced, not recovered.
- Login limits: 10 attempts per address and 200 per client per 15 minutes; both counters live in the process and reset on restart (single-container deployment, documented in `lib/rate-limit.ts`).
