Read-only apart from one POST the route refuses.
- **Release tags for a rebuild-free rollback** (plan scope item 7): `docker-compose.yml` runs `nasmeh-app:${IMAGE_TAG:-latest}`; the runbook's deploy builds with `IMAGE_TAG=$(git rev-parse --short HEAD)`, writes the tag into `.env` and starts it; rollback edits the tag back and `up -d` — no checkout, no build. `restore.sh` restores with the release named in `.env`. `.env.example` and AGENTS.md §6 carry `IMAGE_TAG`.
- **Runbook** ([docs/RUNBOOK.md](../RUNBOOK.md)): Deploy and Rollback rewritten around the tags, a Go-live section pointing at the checklist and the script, the intro updated.

1. **Rollback by tag without a build.** `docker tag nasmeh-app:latest nasmeh-app:91e9cb1` (the step 5 release), then `IMAGE_TAG=91e9cb1 docker compose -f docker-compose.yml up -d --wait` on an empty database: both containers healthy, `docker inspect nasmeh-app-1 --format '{{.Config.Image}}'` = `nasmeh-app:91e9cb1`, `/api/health` up. `docker compose config` shows `nasmeh-app:latest` without the variable and `nasmeh-app:91e9cb1` with it, which is also the name a `build` tags.

## Findings fixed during the step

| # | Finding | Fix |
|---|---|---|
| F1 | The first version of the script followed redirects with `-L --max-redirs 0`, so the admin gate's 307 made curl fail and the row read `307000` | plain `curl` (no following); the row reads `307 location: /prijava?callbackUrl=%2Fadmin` |
| F2 | Harness only: with `MSYS_NO_PATHCONV=1` exported for the docker commands, Git Bash stopped converting the `mktemp` paths for the native `curl.exe` and every request read `000` | the script is unchanged (a Linux host has no such conversion); the pitfall is noted for the workstation |
