# Phase 7, step 4 — Coupons and review moderation

**Date:** 2026-09-10. **Status:** step 4 complete and locally verified on the Windows workstation of the [build-and-verify run](build-verify-2026-09-09.md), on top of commit `6486998` (Phase 7 step 3). Step 5 is next. Every number below was produced in this run.

## Delivered behaviour

- **No migration** (as planned): the `Coupon` model and its `eligibility` / `exclusions` JSON already carried every field the form needs; `BXGY` stays model-only and is listed as a disabled option.
- **Coupons** `/admin/kuponi` (permission `promos:manage`, held by OWNER and MANAGER): search by code, active filter; columns code, type, value, usage (used / total limit), validity window, active, redemptions; create form (code normalised by the same schema as `/koda`, type, percent or amount) that opens the editor.
- **Coupon editor** `/admin/kuponi/[id]`: code, type, percent 1–100 or amount in cents (the value of the other type is cleared on save), active; total and per-customer usage limits, validity window entered as `datetime-local` in the store's time zone (Europe/Ljubljana, whatever zone the server runs in) with the end required to follow the start, minimum spend; eligibility as product, collection and e-mail lists (empty = all) plus excluded products, written into the `eligibility` / `exclusions` JSON that `resolveCouponInput` already reads; stacking stays off and the usage-at-creation note from `lib/copy/promo` is shown. Auto-apply link (absolute `/koda/{CODE}` from the site URL) with a copy button, the QR code as an inline SVG image and a download link at `/admin/kuponi/[id]/qr.svg` (`qrcode` package; the route answers 404 to anyone without the permission), and the redemptions table (order link, e-mail, total, date). A coupon with history (used count or redemptions) can only be deactivated; an unused one can be deleted.
- **Reviews** `/admin/ocene` (permission `reviews:moderate`, held by OWNER, MANAGER and SUPPORT): status links with counts, filters for product (products that have reviews), rating and "only with photos", the verified-purchase line with a link to the order (or "Nepreverjeno mnenje") and the customer's name on each card; the Phase 5 settings form, card actions and data attributes are unchanged, so `reviews.spec.ts` runs as before.
- `lib/koda-code.ts` now holds the coupon code schema without server imports so client components can validate against it (finding F1).

## Findings fixed during the step

| # | Finding | Resolution |
|---|---|---|
| F1 | The first production build failed: the client-side coupon editor imported the form schema from `lib/admin/coupons.ts`, which pulled `lib/koda.ts` and with it `next/headers` into the client bundle | The code schema moved to `lib/koda-code.ts` (re-exported by `lib/koda.ts`) and the form schema to `lib/admin/coupons-schema.ts`; the server module re-exports both |
| F2 | Validity windows were parsed with `new Date("YYYY-MM-DDTHH:mm")`, i.e. in the server's zone — a UTC container would have shifted every window by one or two hours | The schema converts wall-clock input from the store's zone with `Intl` (DST-aware), the editor shows stored instants in that zone, and the list formats windows in it; unit cases cover CET and CEST |

## Deviations from the step 4 design

1. Coupons with history are deactivated rather than deleted (the design did not say); unused coupons can still be deleted from the editor.
2. Eligibility pickers are multi-select lists and an e-mail textarea rather than autocomplete fields — enough for the launch catalog of five products.
3. The review queue filters by product, rating and photo presence as designed; the "with photo" filter is applied after the query because photos live in a JSON array (queues are small).

## Operations notes

- Print the QR from the editor's download link (SVG scales without loss); the link inside encodes the absolute `/koda/{CODE}` URL of `NEXT_PUBLIC_SITE_URL`, so regenerate the QR after a domain change.
- Limited codes are consumed when the order is created, even if the payment fails (Phase 4 design); the editor repeats this note.
- Validity times are entered and shown in Slovenian time regardless of the server's zone.
