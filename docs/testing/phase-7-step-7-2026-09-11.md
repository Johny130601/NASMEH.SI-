## Delivered in this step

- **Review-boss fixes (all four should-fix findings):** the GDPR export route validates the customer id and normalises the guest e-mail with the shared schema before any lookup; the packing-slip and QR routes validate their path params; the order-list filters are a zod schema with fallbacks (`orderFiltersSchema`) shared by the page and the CSV export; the customer list caps its account and guest scans (2 000 / 5 000) and the product and coupon lists cap at 500, each showing "Prikazanih je največ N vnosov; zožite iskanje ali filtre." when a cap is hit; customer detail and guest views cap their order and ticket lists. New unit file `tests/unit/admin-review-fixes.test.ts` (4 cases), `tests/unit/auth-logger.test.ts` (1) and an extended QR guard case.
- **Quiet TOTP hand-over:** the staff password step hands over to the TOTP step through Auth.js's credentials-error channel, which the default logger printed as `[auth][error] CredentialsSignin` on every staff login (step 1 finding, deferred to this step); `lib/auth-logger.ts` drops exactly that error code and keeps every other line, with a unit test.
- **Test hygiene:** `admin-cms.spec.ts` restores its settings and the header menu in `afterEach` like the settings spec (step 6 finding F3), so a timed-out run can no longer leak state into the next.
- **Records and guides:** this record with the §14 checklist; ledger v1.9 (Phase 7 locally accepted), phase plan closed, AGENTS.md §3 lists the admin route segments.
